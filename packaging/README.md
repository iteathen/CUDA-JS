# Packaging

**Status:** Accepted F8W package boundary

CUDA-JS `0.1.0-alpha.15` is a public-manifest, versioned no-addon ESM package with a Node 26.1.0 minimum testing substrate, exact Node 26.7.0 evidence baseline, three explicit exports, immutable compatibility metadata, clean tarball install/uninstall evidence, unrelated synthetic consumers, and exact manifest-verified CUDA 13.3 provider/header profiles. Its additive surface includes typed relocatable PTX, scalar launch kinds through SPEC-0021, typed Device LTO, restricted Device-JS and its accepted atomic/mailbox children, typed Device-JS leaf-library composition, SPEC-0030 dense `f64`/`f16`/`bf16` scalar computation, the ordinary operation lifecycle, device selection/targets, contiguous typed views, SPEC-0020 semantic prepared kernel DAGs, one optional SPEC-0023/SPEC-0029 cuBLASLt f32 row-major matmul profile, and SPEC-0031 bounded prepared composition of those plans. Alpha.15 preserves alpha.14 kernel-only identity and exact launch-limit projection while adding mixed kernel/library replay through one private stream, one whole-DAG operation, library-derived accesses, and plan/view/workspace leases. Dense requests use exact `cuda-numeric` or composite `cuda-device` headers without adding exports, tensor semantics, tensor-core policy, fast math, or performance claims. Prepared replay and library calls return existing operations; neither adds search, arbitrary native control, a public plug-in registry, or CUDA Graph claims. Provider discovery remains lazy. All additive capabilities retain exact profile gates. Device-JS uses pinned `acorn@8.15.0` only as a syntax parser; CUDA-JS owns its accepted grammar, semantics, types, lowering, identity, and CUDA compilation boundary. Structurally admitted native Windows x64 and Linux x64 profiles may operate for testing without a separate opt-in; Linux and later additive native profiles remain not-qualified unless exact evidence says otherwise. CUDA-JS source is AGPL-3.0-or-later with separately negotiated commercial licensing available. Registry publication remains pending a separate release, provenance, and registry review.

ADR-0004/SPEC-0027 authorize an optional NN product only as a separate future publish unit. They add no `cuda-js` export, dependency, workspace, tarball file, compatibility identity, provider discovery, or import side effect. The future NN package name and directory remain unselected, and no NN package or support claim exists.

Shared native engines now source-admit Windows x64 and Linux x64 through thin platform profiles. Windows retains exact accepted evidence; Linux x64 remains `testing-unconfirmed` and not-qualified pending native runners and exact installed-package evidence. Linux ARM64 remains backend-incomplete and WSL2 diagnostic-only. All profiles can install, import, inspect compatibility, and use the mock-only testing export; none gains a native CUDA claim from portable controls.
