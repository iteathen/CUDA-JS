# Packaging

**Status:** Accepted F8W package boundary

CUDA-JS 0.1.0-alpha.8 is a public-manifest, versioned no-addon ESM package with a Node 26.1.0 minimum testing substrate, exact Node 26.7.0 qualification evidence, three explicit exports, immutable compatibility metadata, clean tarball install/uninstall evidence, independent synthetic consumers, and exact manifest-verified CUDA 13.3 compiler/header profiles. The additive public surface includes typed relocatable PTX compilation from SPEC-0010, `u64`/`i32`/`f32` scalar launch kinds from SPEC-0011, `f64`/`f16`/`bf16` scalar launch kinds from SPEC-0021, typed Device LTO from SPEC-0012, restricted Device-JS from SPEC-0013 plus its scoped-atomic-observation, device-publication and SPEC-0014 publication-mailbox children, the opaque one-pending-operation `submit/status/wait/close` lifecycle from SPEC-0016, and SPEC-0017 finite sanitized `discoverCudaDevices()` plus opaque selected-device runtime creation and selected-target defaults. Device publication is exactly naturally aligned `u32`/`u64` release/acquire at device scope; consumer generation, queue and progress policy remain outside CUDA-JS. SPEC-0014 exposes only opaque named directional u32 lanes over private mapped storage with one live operation lease. SPEC-0021 also implements the generic contiguous 1D typed device-view range/lifecycle component used by later accepted consumers, but no public `cuda-js` facade entry for creating views has been selected. These additive capabilities retain exact profile gates. Device-JS uses pinned `acorn@8.15.0` only as a syntax parser; CUDA-JS owns its accepted grammar, semantics, types, lowering, identity, and CUDA compilation boundary. Structurally admitted native Windows x64 and Linux x64 profiles may operate for testing without a separate opt-in; Linux remains not-qualified and operation never promotes support. SPEC-0017 portable mocks do not qualify native selection or distinct-device behavior. CUDA-JS source is licensed under AGPL-3.0-or-later with separately negotiated commercial licensing available. Registry publication remains pending a separate release, provenance, and registry review.

ADR-0004/SPEC-0027 authorize an optional NN product only as a separate future publish unit. They add no `cuda-js` export, dependency, workspace, tarball file, compatibility identity, provider discovery, or import side effect. The future NN package name and directory remain unselected, and no NN package or support claim exists.

Shared native engines now source-admit Windows x64 and Linux x64 through thin platform profiles. Windows retains exact accepted evidence; Linux x64 remains `testing-unconfirmed` and not-qualified pending native runners and exact installed-package evidence. Linux ARM64 remains backend-incomplete and WSL2 diagnostic-only. All profiles can install, import, inspect compatibility, and use the mock-only testing export; none gains a native CUDA claim from portable controls.
