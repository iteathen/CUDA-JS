# Packaging

**Status:** Accepted F8W package boundary

CUDA-JS 0.1.0-alpha.10 is a public-manifest, versioned no-addon ESM package with a Node 26.1.0 minimum testing substrate, exact Node 26.7.0 qualification evidence, three explicit exports, immutable compatibility metadata, clean tarball install/uninstall evidence, independent synthetic consumers, and exact manifest-verified CUDA 13.3 compiler/header profiles. The additive public surface includes typed relocatable PTX compilation from SPEC-0010, scalar launch kinds through SPEC-0021, typed Device LTO, restricted Device-JS and its accepted atomic/mailbox children, typed Device-JS leaf-library composition from SPEC-0028, the SPEC-0016 operation lifecycle, SPEC-0017 device selection/target defaults, and allocation-owned contiguous SPEC-0021 typed-view capabilities. Library composition uses explicit aliased imports, copied identity-bearing artifacts, deterministic non-caller-selected symbols, and the existing RDC/LTO linker owner; it adds no tensor or native-control semantics. These additive capabilities retain exact profile gates. Device-JS uses pinned `acorn@8.15.0` only as a syntax parser; CUDA-JS owns its accepted grammar, semantics, types, lowering, identity, and CUDA compilation boundary. Structurally admitted native Windows x64 and Linux x64 profiles may operate for testing without a separate opt-in; Linux, native view use, and native library composition remain not-qualified. CUDA-JS source is AGPL-3.0-or-later with separately negotiated commercial licensing available. Registry publication remains pending a separate release, provenance, and registry review.

ADR-0004/SPEC-0027 authorize an optional NN product only as a separate future publish unit. They add no `cuda-js` export, dependency, workspace, tarball file, compatibility identity, provider discovery, or import side effect. The future NN package name and directory remain unselected, and no NN package or support claim exists.

Shared native engines now source-admit Windows x64 and Linux x64 through thin platform profiles. Windows retains exact accepted evidence; Linux x64 remains `testing-unconfirmed` and not-qualified pending native runners and exact installed-package evidence. Linux ARM64 remains backend-incomplete and WSL2 diagnostic-only. All profiles can install, import, inspect compatibility, and use the mock-only testing export; none gains a native CUDA claim from portable controls.
