- [`SPEC-0013-restricted-device-js.md`](SPEC-0013-restricted-device-js.md) — accepted restricted Device-JS frontend for consumer-neutral typed JavaScript source, deterministic private CUDA C++ lowering, and CompilerActor reuse without consumer CUDA syntax.
- [`SPEC-0013-public-surface-addendum.md`](SPEC-0013-public-surface-addendum.md) — accepted SPEC-0013 clarification for the standalone public helper, code-unit determinism, conservative non-void return completeness, standalone-only void synchronization helpers, and syntax-only parser ownership.
- [`SPEC-0014-long-lived-sideband.md`](SPEC-0014-long-lived-sideband.md) — accepted bounded publication-mailbox profile with opaque named u32 lanes, private registered/mapped backing, system-scope acquire/release Device-JS helpers, and SPEC-0016 operation leases.

- [`SPEC-0017-device-selection-and-target-resolution.md`](SPEC-0017-device-selection-and-target-resolution.md) — accepted and portable/software/package-implemented bounded foundation for sanitized opaque device selection, one selected device per runtime, and selected-device-driven compile/link target resolution; native qualification remains separate.

- [`SPEC-0019-host-memory-and-async-transfer.md`](SPEC-0019-host-memory-and-async-transfer.md) — accepted exact first profile for two internal pinned staging blocks and contiguous H2D/D2H/D2D operations over the accepted operation lifecycle.

No production implementation is authorized merely because a function appears in generated schema, a proposal exists, an historical specification exists, or an issue is open. Production work must remain inside the exact bounds of current accepted CUDA-JS authority; native/support claims additionally require their exact evidence gates.
