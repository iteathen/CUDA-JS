# Specifications

**Status:** Informational

- [`SPEC-0000-runtime-contract-map.md`](SPEC-0000-runtime-contract-map.md) — proposal map of version-zero contract families, dependency order, hard requirements, and exclusions.
- [`SPEC-0001-cuda-schema-compiler.md`](SPEC-0001-cuda-schema-compiler.md) — accepted F1B contract for pinned header facts, reviewed Tier-0 semantics, normalized Runtime IR, generated products, and Linux x86-64 native ABI probes.
- [`SPEC-0002-windows-driver-bootstrap.md`](SPEC-0002-windows-driver-bootstrap.md) — accepted Windows-only F2W contract for canonical Driver discovery, generated bindings, procedure verification, independent MSVC parity, permissions, private context lifecycle, and cleanup.
- [`SPEC-0003-driver-actor-resource-lifecycle.md`](SPEC-0003-driver-actor-resource-lifecycle.md) — accepted Windows-first F3 contract for the async DriverActor, opaque registry, health/error state, graceful teardown, unexpected-loss behavior, and platform-neutral lifecycle mock.
- [`SPEC-0003-disposal-failure-addendum.md`](SPEC-0003-disposal-failure-addendum.md) — accepted correction preserving disposal/native-cleanup category, observation, health and orphan truth instead of collapsing failures into ordinary `stale-resource` rejection.
- [`SPEC-0004-device-memory-foundation.md`](SPEC-0004-device-memory-foundation.md) — accepted Windows-first F4 contract for bounded device allocations, copied host transfers, quotas, leases, release, teardown, and portable memory lifecycle validation.
- [`SPEC-0005-module-launch-completion.md`](SPEC-0005-module-launch-completion.md) — accepted Windows-first F5 contract for bounded PTX modules, declared functions, packed launches, one private stream, event-polled completion, deferred-error attribution, and portable execution lifecycle validation.
- [`SPEC-0006-compiler-linker-cache.md`](SPEC-0006-compiler-linker-cache.md) — accepted Windows-first F6 contract for a separate CompilerActor, canonical NVRTC/nvJitLink providers, typed options, PTX/cubin artifacts, validated content-addressed cache, and DriverActor handoff.
- [`SPEC-0006-target-syntax-addendum.md`](SPEC-0006-target-syntax-addendum.md) — accepted correction centralizing CUDA target parsing/policy, representing current numeric/`f`/`a` target syntax while policy-admitting only reviewed targets and keeping provider/device/qualification state separate.
- [`SPEC-0007-windows-platform-hardening.md`](SPEC-0007-windows-platform-hardening.md) — accepted Windows-first F7 contract for sanitized platform diagnostics, WDDM/TCC/watchdog facts, permission profiles, deterministic failure/property partitions, and repeated lifecycle stress with retained Linux/WSL handoffs.
- [`SPEC-0008-package-public-facade.md`](SPEC-0008-package-public-facade.md) — accepted Windows-first F8 contract for the no-addon package, safe public facade, compatibility policy, independent consumer, install/uninstall evidence, and portable Linux handoff.
- [`SPEC-0009-trusted-toolkit-headers-and-cuda-mcgs-interop.md`](SPEC-0009-trusted-toolkit-headers-and-cuda-mcgs-interop.md) — accepted bounded F9 contract for a manifest-verified CUDA CCCL virtual-header profile and generic atomic-publication capability, without consumer semantics.
- [`SPEC-0010-relocatable-device-code.md`](SPEC-0010-relocatable-device-code.md) — accepted bounded CompilerActor follow-up for typed NVRTC relocatable-device-code compilation and linkable PTX metadata while preserving the existing default compile/link path.
- [`SPEC-0011-scalar-kernel-arguments.md`](SPEC-0011-scalar-kernel-arguments.md) — accepted bounded execution follow-up adding closed `u64`, `i32`, and finite-only `f32` packed scalar argument kinds while preserving legacy launch behavior.
- [`SPEC-0012-device-lto.md`](SPEC-0012-device-lto.md) — accepted bounded CompilerActor follow-up adding typed LTO-IR compile output and homogeneous device-LTO linking without exposing raw nvJitLink controls.
- [`SPEC-0013-restricted-device-js.md`](SPEC-0013-restricted-device-js.md) — accepted restricted Device-JS frontend for consumer-neutral typed JavaScript source, deterministic private CUDA C++ lowering, and CompilerActor reuse without consumer CUDA syntax.
- [`SPEC-0013-public-surface-addendum.md`](SPEC-0013-public-surface-addendum.md) — accepted SPEC-0013 clarification for the standalone public helper, code-unit determinism, conservative non-void return completeness, standalone-only void synchronization helpers, and syntax-only parser ownership.
- [`SPEC-0014-long-lived-sideband.md`](SPEC-0014-long-lived-sideband.md) — accepted bounded publication-mailbox profile with opaque named u32 lanes, private registered/mapped backing, system-scope acquire/release Device-JS helpers, and SPEC-0016 operation leases.
- [`SPEC-0015-execution-scope-status-clarification.md`](SPEC-0015-execution-scope-status-clarification.md) — accepted clarification that SPEC-0005 single-flight exclusions are F5 scope/qualification boundaries, not architectural rejection.
- [`SPEC-0016-operation-lifecycle.md`](SPEC-0016-operation-lifecycle.md) — accepted submission/completion lifecycle: one opaque operation, one DriverActor/context, one private stream and one pending operation in the first slice, with strict pending-command gating and preserved terminal `launch()` compatibility.
- [`SPEC-0017-device-selection-and-target-resolution.md`](SPEC-0017-device-selection-and-target-resolution.md) — accepted bounded foundation for sanitized opaque device selection, one selected device per runtime, and selected-device-driven compile/link target resolution; implementation/native qualification remain separate.
- [`SPEC-0018-bounded-multi-operation-scheduling.md`](SPEC-0018-bounded-multi-operation-scheduling.md) — accepted bounded generalization of SPEC-0016 to two private streams and at most two in-flight operations, with explicit dependencies, hazards, backpressure and conservative failure attribution.
- [`SPEC-0019-host-memory-and-async-transfer.md`](SPEC-0019-host-memory-and-async-transfer.md) — accepted exact first profile for two internal pinned staging blocks and contiguous H2D/D2H/D2D operations over the accepted operation lifecycle.
- [`SPEC-0020-prepared-batch-and-graph-execution.md`](SPEC-0020-prepared-batch-and-graph-execution.md) — proposal for finite prepared operation DAGs with ordinary-operation semantic baseline and optional private CUDA Graph realization.
- [`SPEC-0021-extended-numeric-abi-and-device-views.md`](SPEC-0021-extended-numeric-abi-and-device-views.md) — accepted bounded foundation for `f64`/`f16`/`bf16` scalar packing plus contiguous one-dimensional typed views over opaque device allocations; legacy SPEC-0011 `f32` remains finite-only.
- [`SPEC-0022-device-js-parallel-and-service-profiles.md`](SPEC-0022-device-js-parallel-and-service-profiles.md) — proposal separating trusted-source Device-JS parallel primitives from a later bounded service-safe profile.
- [`SPEC-0022-scoped-atomic-observation-addendum.md`](SPEC-0022-scoped-atomic-observation-addendum.md) — accepted bounded child adding explicit relaxed device-scope `u32`/`u64` atomic load/store helpers without snapshot or unrelated-memory ordering guarantees.
- [`SPEC-0023-context-bound-cuda-library-adapters.md`](SPEC-0023-context-bound-cuda-library-adapters.md) — proposal for finite context-bound optional CUDA library/provider adapters and first cuRAND/cuSPARSE/cuFFT consumers.
- [`SPEC-0024-multi-gpu-orchestration.md`](SPEC-0024-multi-gpu-orchestration.md) — proposal for finite multi-GPU coordination, device-scoped resources, peer/staged copies and heterogeneous per-device artifacts.
- [`SPEC-0025-graphics-interop.md`](SPEC-0025-graphics-interop.md) — proposal for API-specific opaque external graphics memory/synchronization interoperability with exact device matching and ownership epochs.
- [`SPEC-0026-process-isolated-execution.md`](SPEC-0026-process-isolated-execution.md) — proposal for child-process Driver/compiler backends, bounded IPC, process epochs and supervised recovery without fabricating CUDA cleanup.
- [`SPEC-0027-nn-extension-foundation.md`](SPEC-0027-nn-extension-foundation.md) — accepted authority-only foundation for an optional separately packaged NN product, planned ownership anchors, core isolation, and child-specification gates; no NN implementation or qualification.

SPEC-0003, SPEC-0006, SPEC-0014, SPEC-0017 through SPEC-0019, scoped-atomic SPEC-0022 addenda, and SPEC-0021 are accepted authority. SPEC-0020, the remainder of SPEC-0022, and SPEC-0023 through SPEC-0026 remain proposal authority only. SPEC-0027 is accepted product/package/component authority only; its planned anchors do not authorize production code without separately accepted child specifications.

No production implementation is authorized merely because a function appears in generated schema, a proposal exists, or an issue is open. Production work must remain inside the exact bounds of an accepted specification; native/support claims additionally require their exact evidence gates.
