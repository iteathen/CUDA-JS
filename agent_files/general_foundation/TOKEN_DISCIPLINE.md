# Token Discipline

Treat token use as backpressure on every task, not as a reason to sacrifice engineering quality.

## Objective

Optimize verified coherent progress per total lifecycle token: correctness, rework avoided, evidence reused, integration completed, cleanup finished, and continuation cost minimized.

## Practice floor

Never save tokens by omitting material authority, exact revisions, shared-contract meaning, failure/resource behavior, evidence, cleanup, review, or handoff state.

## Reduction ladder

When pressure rises:

1. stop adding scope and polish;
2. search/index before broad reading;
3. load exact diffs, owning sections, filtered logs, and accepted output contracts;
4. batch independent retrievals and consolidate related tests;
5. reuse unchanged evidence with explicit identity/invalidation checks;
6. checkpoint and hand off before context can no longer support a complete cycle.

## Reserve

Before substantial mutation reserve enough context for actual-effect inspection, falsification, integration, cleanup, review, handoff, and one bounded recovery cycle. Do not spend that reserve on speculative architecture or optimization.

## Context layers

Load operating kernel, owning authority, local mechanism, consequence horizon, then rationale/provenance only when needed. Do not repeatedly reread unchanged authority or sibling transcripts.

## Pressure states

- **Green:** full act/inspect/falsify/reconcile cycle fits.
- **Yellow:** open no new broad unknown; finish or safely pause current work.
- **Red:** stop new mutation; preserve exact state and clean/quarantine unsafe partial work.
- **Emergency:** use remaining capacity only for authority, revisions, failures, cleanup, and next safe action.

Missing durable decisions, branch outputs, failure evidence, partial state, or cleanup obligations create token debt and block completion.
