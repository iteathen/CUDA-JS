# Focus Branches

A focus branch is a semantic work packet, not automatically a Git branch.

## When required

Use a focus-branch map when work:

- exceeds one focused session;
- spans independent owners, contracts, paths, or unknowns;
- crosses agents/sessions/repositories;
- would force skimming or sampling;
- benefits from parallelism with separable write surfaces.

## Parent integration spine

One canonical parent owns the global outcome, authority, vocabulary, invariants, dependency graph, invalidation, contradictions, cleanup, and final closure.

## Leaf packet

Each material leaf states:

- stable ID and parent-plan version;
- owner and exact input revisions;
- scope/non-goals and write permissions;
- preserved global invariants;
- output contract;
- acceptance/falsifier;
- invalidation rules;
- cleanup and integration obligations.

Size it so one agent can retain the owner, mechanism, dependencies, failure/resource behavior, evidence, consequence horizon, and cleanup without skimming.

## Parallelism and reconciliation

Parallelize only with non-overlapping ownership/write surfaces, frozen or coordinated shared contracts, acyclic dependencies, and one integration owner. Local branch acceptance never proves parent completion; centrally reconcile boundaries, end-to-end behavior, lifecycle, resources, compatibility, security, performance, and cleanup.
